# Papers: curated reading list and catalog

Curated notes are mine and say why the paper matters for the argument. The catalog that follows
is generated from the arXiv API (metadata is CC0) and lists every 2026 paper matched by the
containment-related queries, newest first, with the opening sentence of its abstract.

## Curated: 2026 papers by theme

### Incidents and what they teach

- **From Reactive Containment to Proactive Assurance: Lessons from OpenAI, Anthropic, and Google Agent Security Incidents** (2026-10-08) — Cross-lab reading of the 2026 OpenAI, Anthropic and Google incidents; argues for assurance designed in advance. The academic companion to this piece.  
  <https://arxiv.org/abs/2610.12463>
- **GROB: A Multi-Agent Architecture for Public-Trace Investigation of Candidate Agentic Activity** (2026-10-08) — How to investigate suspected agent activity from public traces when you have no privileged telemetry. Relevant to the volunteer-sleuth story.  
  <https://arxiv.org/abs/2610.11467>
- **Ecology of AI Agents: Collaboration Creates a Population Threshold for Takeoff** (2026-10-08) — Models the population dynamics of misaligned agents that can compromise machines and deploy more agents. Frames why coordination channels matter.  
  <https://arxiv.org/abs/2610.12436>

### Runtime enforcement and guard models

- **One Word Opens the Gate: The Option-Channel Attack on Typed Decision Models as Agent Guardrails** (2026-10-08) — Typed decision models used as guardrails can be flipped by wording in the thing they judge. Evidence that a classifier is a weaker boundary than a rule.  
  <https://arxiv.org/abs/2610.12292>
- **Safe Actions Alone Do Not Ensure Safe Agents: Identifying Unfulfilled Obligations with Guard Models** (2026-10-08) — Guard models that only forbid actions miss required actions left undone. Containment has obligations, not just prohibitions.  
  <https://arxiv.org/abs/2610.11773>
- **Formal Runtime Verification for Tool-Using LLM Agents: An Offline Same-Benchmark Study on AgentDojo and STAC** (2026-10-07) — Metric first-order temporal logic as a declarative, auditable policy language, replayed over AgentDojo and STAC trajectories.  
  <https://arxiv.org/abs/2610.09793>
- **Practical Runtime Enforcement of First-Order Temporal Requirements** (2026-10-03) — Enforcers that handle obligations on future behaviour, the kind agent security policies actually need.  
  <https://arxiv.org/abs/2610.04611>
- **ActGov: Governing LLM Agent Actions via Policy-Constrained Validation** (2026-09-21) — Policy-constrained validation of agent actions at runtime.  
  <https://arxiv.org/abs/2609.24446>
- **Hard Stop: Kernel-Level Preemption and Containment for Rogue Agentic Execution** (2026-09-24) — Kernel-level preemption and containment for runaway agentic execution. The OS as the enforcement point.  
  <https://arxiv.org/abs/2609.29808>
- **ContractWarden: Kernel-Enforced Damage Boundaries for AI Agents via Human-Authorized Contracts** (2026-09-29) — Kernel-enforced damage boundaries defined by human-authorised contracts.  
  <https://arxiv.org/abs/2609.38248>
- **Symbolic Temporal Supervision of LLM Agents Using Contracts** (2026-09-16) — Contracts as the supervision mechanism for long-running agents.  
  <https://arxiv.org/abs/2609.18128>
- **Certified Multi-Source Integrity for Structured Agent Actions** (2026-09-28) — Integrity guarantees for structured actions assembled from several untrusted sources.  
  <https://arxiv.org/abs/2609.34245>
- **OnTrack: Real-Time Monitoring and Intervention in LLM Agent Trajectories via Streaming Structure-Aware Optimal Transport** (2026-10-08) — Streaming monitoring and intervention in trajectories, aimed at irreversible actions.  
  <https://arxiv.org/abs/2610.12375>
- **Cadence: Strategic Guidance for Coding Agents** (2026-10-08) — When runtime monitors should intervene; static triggering limits their value.  
  <https://arxiv.org/abs/2610.12269>
- **Persona Guardrail: A Production-Grade Defense Framework for Agentic Systems** (2026-10-02) — A production framework that goes beyond attack-specific guardrails.  
  <https://arxiv.org/abs/2610.03434>
- **Constrained-Action AI Remediation for SIEM/XDR via a NeMo-Guardrails Proxy** (2026-10-07) — Agents that issue security-operations commands through a constrained proxy. A concrete bounded-action design.  
  <https://arxiv.org/abs/2610.09906>
- **Multi-Aspect Runtime Verification for Simulation-Based V&V of LLM-Enabled Autonomous Agents** (2026-10-06) — When retraining is not available, the interface is the only thing under engineering control. Applies to anyone consuming models as procured components.  
  <https://arxiv.org/abs/2610.08928>
- **Evaluating Bounded Autonomy in Regulated Agentic AI: A Diagnostic Harness with Constitutional Rewards, Escalation Labels, and Runtime Governance** (2026-09-28) — A diagnostic harness for bounded autonomy with constitutional rules in regulated settings.  
  <https://arxiv.org/abs/2609.37501>

### Permissions, capabilities and least privilege

- **PACE: Provenance-Aware Capability Enforcement for Tool-Using LLM Agents** (2026-10-01) — Capabilities tied to the provenance of what steered the call, because vetting an artifact at admission cannot distinguish a safe variant from a leaking one.  
  <https://arxiv.org/abs/2610.01349>
- **MetaPermit: Scalable and Auditable Access Control for AI Agents via LLM-Inferred Meta-Attributes** (2026-09-25) — Scalable, auditable access control for agents via inferred meta-attributes.  
  <https://arxiv.org/abs/2609.31039>
- **Aletheia: Permission-Minimality Testing for Coding-Agent Rules** (2026-09-30) — Tests whether repository rule files request more authority than the task needs. Directly relevant to AGENTS.md convergence.  
  <https://arxiv.org/abs/2609.39678>
- **What May an Agent Change About Itself? A Containment Floor for Self-Configuring Agent Runtimes** (2026-10-05) — A containment floor for runtimes that let agents edit their own configuration: which settings must be outside the agent's reach.  
  <https://arxiv.org/abs/2610.06274>
- **Containing the Autonomous Operator: A Defense-in-Depth Framework and Reference Architecture for Securing AI Agents on Kubernetes** (2026-10-02) — Defense-in-depth reference architecture for agents operating Kubernetes, where the data-versus-control boundary collapses.  
  <https://arxiv.org/abs/2610.02861>
- **HarnessSecurity-Bench: Do Security Mechanisms Really Protect Coding Agent Harnesses?** (2026-10-06) — First systematic study of the security mechanisms in coding-agent harnesses, with a ten-mechanism taxonomy. Shows how uneven they are.  
  <https://arxiv.org/abs/2610.07639>
- **Let the Agent Do It? How Software Practitioners Understand and Make Permission Decisions in Agentic AI Assistants** (2026-10-05) — Qualitative study of how developers actually make permission decisions. Pairs with the Scale X numbers.  
  <https://arxiv.org/abs/2610.06047>
- **CredLeakBench: Evaluating Credential Leakage and Recovery in LLM Agents** (2026-10-06) — Measures credential leakage and recovery in agents handling everyday tasks under phishing.  
  <https://arxiv.org/abs/2610.08871>
- **Agentic-ZTA: A Multi-Agent Architecture for Autonomous Zero Trust Enforcement** (2026-10-05) — Zero-trust enforcement operated by agents; the inverse problem, useful for vocabulary.  
  <https://arxiv.org/abs/2610.05782>

  <https://arxiv.org/abs/2610.05640>
- **APEX: Active Protection at Execution Boundaries for LLM Agents** (2026-10-03) — Protection at the point of execution rather than pattern recognition, as tools, MCP servers and skills multiply the carriers.  
  <https://arxiv.org/abs/2610.06966>
- **Blocking at the Boundary: Auditing Long-Horizon Agents against Staged Prompt Injection** (2026-10-04) — Staged injection that propagates across causally connected steps; audits at the boundary.  
  <https://arxiv.org/abs/2610.05163>
- **AgentTracer: Tracing Indirect Prompt Injection Attack through Fine-Grained Intention-Execution Alignment** (2026-10-07) — Post-incident tracing of indirect injection by aligning intention and execution. For the evidence plane.  
  <https://arxiv.org/abs/2610.09935>
- **Readable Before Actionable: Causal Tracing of Indirect Prompt Injection** (2026-10-04) — Mechanistic look at where an injected instruction becomes an action.  
  <https://arxiv.org/abs/2610.05295>
- **Package Hallucination Attacks on Coding Agents through Prompt Injection in Rule Files** (2026-10-07) — Shared rule files (AGENTS.md, .cursorrules) as an attack surface. Topical given the AGENTS.md convergence.  
  <https://arxiv.org/abs/2610.09264>
- **Beyond Single-Model Injection: A Threat Model and Defense Architecture for Prompt Injection in Multi-Agent Systems** (2026-09-19) — Threat model and defense architecture for injection across multi-model pipelines.  
  <https://arxiv.org/abs/2609.22949>
- **RAISED: Self-Distillation for Robustness to Prompt Injection in LLM Agents** (2026-10-05) — Training-time defense that avoids the capability drift other training defenses cause. Shows the model-side ceiling.  
  <https://arxiv.org/abs/2610.06401>
- **Towards a Unified Misuse Monitoring Benchmark** (2026-10-05) — Decomposition attacks and injection treated together, as a monitoring problem.  
  <https://arxiv.org/abs/2610.07089>
- **ASPIRE: Agentic Safety & Prompt Injection Red-teaming Engine** (2026-10-06) — Automated red-teaming across an agent's behaviour space rather than fixed scenarios.  
  <https://arxiv.org/abs/2610.08951>

## Background: the papers the 2026 work builds on

  <https://arxiv.org/abs/2302.12173>
- **Identifying the Risks of LM Agents with an LM-Emulated Sandbox** (2023-09-25) — ToolEmu: an LM-emulated sandbox for finding agent risks before deployment.  
  <https://arxiv.org/abs/2309.15817>
- **InjecAgent: Benchmarking Indirect Prompt Injections in Tool-Integrated Large Language Model Agents** (2024-03-05) — InjecAgent: the first benchmark of indirect injection in tool-using agents.  
  <https://arxiv.org/abs/2403.02691>
- **GuardAgent: Safeguard LLM Agents by a Guard Agent via Knowledge-Enabled Reasoning** (2024-06-13) — GuardAgent: a guard agent that reasons over knowledge to safeguard another agent.  
  <https://arxiv.org/abs/2406.09187>
- **AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents** (2024-06-19) — AgentDojo: the standard dynamic environment for injection attacks and defenses; still the benchmark the 2026 runtime-verification papers replay.  
  <https://arxiv.org/abs/2406.13352>
- **Permissive Information-Flow Analysis for Large Language Models** (2024-10-04) — Permissive information-flow analysis: tracking what untrusted data may influence.  
  <https://arxiv.org/abs/2410.03055>
- **AgentHarm: A Benchmark for Measuring Harmfulness of LLM Agents** (2024-10-11) — AgentHarm: measuring how readily agents carry out harmful tasks.  
  <https://arxiv.org/abs/2410.09024>
- **Frontier Models are Capable of In-context Scheming** (2024-12-06) — Frontier models are capable of in-context scheming (Apollo).  
  <https://arxiv.org/abs/2412.04984>
- **The Task Shield: Enforcing Task Alignment to Defend Against Indirect Prompt Injection in LLM Agents** (2024-12-21) — Task Shield: enforcing task alignment to defend against indirect injection.  
  <https://arxiv.org/abs/2412.16682>
- **Firewalls to Secure Dynamic LLM Agentic Networks** (2025-02-03) — Firewalls for dynamic agentic networks.  
  <https://arxiv.org/abs/2502.01822>
- **SafeArena: Evaluating the Safety of Autonomous Web Agents** (2025-03-06) — SafeArena: safety of autonomous web agents.  
  <https://arxiv.org/abs/2503.04957>
- **Defeating Prompt Injections by Design** (2025-03-24) — CaMeL (Defeating Prompt Injections by Design): separate trusted control flow from untrusted data and enforce capabilities. The architectural idea the whole topic turns on.  
  <https://arxiv.org/abs/2503.18813>
- **AgentSpec: Customizable Runtime Enforcement for Safe and Reliable LLM Agents** (2025-03-24) — AgentSpec: customisable runtime enforcement for agents; the 2025 ancestor of the 2026 enforcement papers.  
  <https://arxiv.org/abs/2503.18666>
- **ShieldAgent: Shielding Agents via Verifiable Safety Policy Reasoning** (2025-03-26) — ShieldAgent: verifiable safety-policy reasoning as a shield.  
  <https://arxiv.org/abs/2503.22738>
- **MCP Safety Audit: LLMs with the Model Context Protocol Allow Major Security Exploits** (2025-04-02) — MCP Safety Audit: early demonstration that MCP tooling enables major exploits.  
  <https://arxiv.org/abs/2504.03767>
- **Design Patterns for Securing LLM Agents against Prompt Injections** (2025-06-10) — Design patterns for securing agents against injection (the six-pattern paper); the practitioner's reference.  
  <https://arxiv.org/abs/2506.08837>
- **Agentic Misalignment: How LLMs Could Be Insider Threats** (2025-10-05) — Agentic Misalignment (Anthropic): models as potential insider threats in simulated corporate settings.  
  <https://arxiv.org/abs/2510.05179>
